# InfraSecBench: A Large-Scale Security Evaluation of LLM-Generated Cloud Infrastructure Code

## Overview

This project evaluates the security posture of Infrastructure-as-Code (Terraform, CloudFormation, ARM Templates, Kubernetes) generated by frontier Large Language Models across major cloud providers (AWS, GCP, Azure). The goal is to build an automated pipeline that generates code from realistic deployment scenarios, scans the code using industry-standard security tools, and aggregates the results into a comprehensive research paper.

## Design Decisions (Resolved)

| Decision | Resolution |
|---|---|
| **LLM Selection** | Cloud-based frontier models only (16GB RAM rules out local LLMs): GPT-5, Claude Opus 4, Gemini 2.5 Pro |
| **IaC Tools & Providers** | Equal coverage across Terraform, CloudFormation, ARM Templates, and Kubernetes |
| **Cloud Providers** | AWS, Azure, GCP, plus cloud-agnostic Kubernetes |
| **Orchestration** | Python-based orchestrator (`src/orchestrator.py`) |
| **Paper Format** | LaTeX — deferred until results are ready |
| **Scenarios** | 60 realistic deployment prompts (10 per tool/provider combination) |

### Generation Pipeline

#### [NEW] `src/generate_iac.py`
- Uses `litellm` to provide a unified interface to cloud LLM APIs.
- Iterates through `data/scenarios.json`.
- Prompts each LLM with a system prompt enforcing code-only output.
- Extracts the code block from the response via regex.
- Saves output to `data/generated/{model_name}/{scenario_id}/main.{tf|yaml|json}`.
- Idempotent: skips already-generated files on re-runs.
- CLI flags: `--model`, `--temperature`, `--dry-run`.

**Model Registry:**
| Short Name       | litellm Model ID          |
|------------------|---------------------------|
| `gpt-5`          | `openai/gpt-5`            |
| `claude-opus-4`  | `anthropic/claude-opus-4`  |
| `gemini-2.5-pro` | `gemini/gemini-2.5-pro`    |

---

### Scanning Pipeline

#### [NEW] `src/run_scanners.py`
- Discovers all generated IaC files in `data/generated/`.
- Uses Python's `subprocess` module to execute locally installed versions of:
  - **Checkov** (`checkov -d <dir> -o json --quiet --compact`)
  - **tfsec** (`tfsec <dir> --format json --no-color`)
  - **Trivy** (`trivy config <dir> -f json --quiet`)
- Checks scanner availability on PATH before running.
- 2-minute timeout per scan to prevent hangs.
- Saves raw JSON outputs into `data/scan_results/{model_name}/{scenario_id}/`.
- CLI flags: `--scanner`, `--model`.

---

### Parsing & Aggregation

#### [NEW] `src/parse_results.py`
- Reads JSON outputs from Checkov, tfsec, and Trivy.
- Normalises findings (rule IDs, severity, descriptions, pass/fail status).
- Maps rule IDs to CIS Benchmark categories via keyword matching across 6 categories:
  - Identity and Access Management
  - Logging and Monitoring
  - Networking
  - Data Protection
  - Compute and Container Security
  - Storage
- Exports: `findings_raw.csv`, `summary_model_scanner.csv`, `summary_severity.csv`, `summary_cis_category.csv`, `summary_pass_rate.csv`.
- CLI flags: `--format csv|markdown`.

---

### Visualisation

#### [NEW] `src/visualise.py`
- Reads summary CSVs and generates publication-ready charts:
  - Grouped bar chart: fail counts by model × scanner
  - Stacked bar chart: severity distribution by model
  - Heatmap: CIS category failures across models
  - Grouped bar chart: pass rates by model × scanner
- Outputs to `paper/figures/` at 300 DPI.

---

### End-to-End Orchestrator

#### [NEW] `src/orchestrator.py`
- Chains all 4 steps sequentially: Generate → Scan → Parse → Visualise.
- CLI flags: `--skip-gen`, `--skip-scan`, `--skip-parse`, `--skip-viz`, `--dry-run`, `--model`.

## Verification Plan

### Automated/Manual Verification
1. **Dry Run**: Run `python src/generate_iac.py --dry-run` to verify prompt construction.
2. **Single-Model Test**: Run `python src/generate_iac.py --model gpt-5` on a few scenarios.
3. **Scanner Execution**: Run `python src/run_scanners.py --model gpt-5` to verify scanner integration.
4. **Parsing Logic**: Run `python src/parse_results.py --format markdown` to verify CIS mapping and aggregation.
5. **Visualisation**: Run `python src/visualise.py` to confirm chart generation.
6. **Full Pipeline**: Run `python src/orchestrator.py` end-to-end.
